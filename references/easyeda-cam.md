# 现场执行与实铜验收

准备开始布线时，先核对[布局审查检查点](placement-routing.md#布局审查与继续布线)及批准范围。修改超出批准布局时，回到受影响部分的人工审查。保存回执、DRC 和 CAM 结果分别证明对应检查结果，人工确认单独记录。

## 阶段复验

布局与布线中先按[设计规则](placement-routing.md#设计时使用规则)作决定。改变器件面别、线宽、过孔、叠层或板框后，将受影响的检查标为待复验。执行[集中布线与阶段铺铜](placement-routing.md#集中布线与阶段铺铜)策略。阶段验收时恢复暂时停用的铺铜并统一重建，确认受影响区域填充已更新，再验证连接、间距、供电和回流，运行相应 DRC。依赖平面的待确认连接须逐项关闭；旧铜面、孤立护线和未填充边界不能作为通过证据。需要 CAM 核验时从该修订集中导出，后续改动使受影响结果失效；最终全板验收使用统一重建后的实铜和全板 DRC。

最终复查沿用设计时的适用条件，不把可选建议升级为通用硬门槛：

| 发生过的设计或修改 | 在最终版本上复查 |
|---|---|
| 原理图/ECO、参考电路或测量接法变化 | 原理图、实际焊盘网表和 PCB 修订对应；测流位置、仪器接地、量程/误差与储能边界仍符合目标。 |
| 安装孔、接地合网、Net-Tie 或机械铜变化 | 孔及垫圈包络、全层避空、铜的电气归属和实际连接；浮铜不误接地，指定连接点没有被其它铜绕过。 |
| 差分调长、泪滴、侧地或换层变化 | 实际端点间主通路、支路负载、参考连续性、局部阻抗与对称性；电源最窄截面和 Kelvin 接点不因修形受损。 |

这些复查由 Codex 结合源文件、器件/工厂资料和分析证据完成，必要时提交人工或实测确认。后端 DRC 只覆盖该版本支持且启用的规则；`board-job.mjs` 负责作业执行和回执，`cam-check.py` 负责其支持格式与分辨率内的连通检查。它们不自动判定参考电路适用性、机械接触是否合理、阻抗/串扰、去耦效果或功耗测量精度。

迭代候选按具体对象列既有、消除、新增及恶化项，报告受影响网络和邻域。几何近距筛查记录阈值、层范围及采样分辨率，结论限于该检测范围。参考覆盖同时列未覆盖总长和连续缺口，供电抽样截面注明方向及覆盖范围。零新增项和总数下降仍需结合未解决项判断交付状态。

分别记录 ERC、逐脚网表、原生 DRC、CAM 和功能/实测状态。缺少证据时写明影响范围和确认方法，按本次交付点决定能否继续试布或交付。

## 先辨认文档，再运行命令

本节命令用于 easyeda-api 路径。PcbCliTool 路径使用其版本对应的原生命令保存、检查和导出，再按下文核对同版制造文件。

准备 Node 18+ 和 easyeda-api 网关。按该技能的文档发现本机端口，查 `/health`、`/eda-windows` 和 `eda.dmt_Project.getCurrentProjectInfo()`；从工程树取得目标板 UUID，切至该板。多个窗口时用环境变量 `EASYEDA_WINDOW_ID` 指定目标；端口可用 `EASYEDA_BRIDGE_PORT` 覆盖。下列命令从本技能目录运行，将 PROJECT、BOARD 和输出文件替换为实际值。每个输出路径须为新文件，父目录须存在。

```text
node scripts/board-job.mjs snapshot PROJECT BOARD before.epcb
node scripts/board-job.mjs pour-save PROJECT BOARD pour-receipt.json
node scripts/board-job.mjs drc PROJECT BOARD drc.json
node scripts/board-job.mjs gerber PROJECT BOARD check.zip
```

`snapshot` 适用于已放置器件的板。`pour-save` 是上述命令中唯一会修改并保存板图的命令，仅在用户要求的板与阶段使用；需已有铺铜边界。它枚举铺铜对象，逐个执行 `rebuildCopperRegion()`，记录成功对象并保存。此顺序在 easyeda-api 1.1.36、嘉立创EDA 4.1.99 的桌面工程验证过。关闭、重开并读回填充几何可验证持久性。判断“实铜一致”时按区域比对轮廓、内孔、层别，容许有记录的序列重排和远小于制造精度的浮点差。

长任务在扩展内运行一次，客户端脚本轮询同一作业编号。超时后用原命令追加打印出的 JOB_UUID 查询。扩展重新加载可能使内存状态失效；此时先读回现场再判断是否要继续。逐区重建中途失败可能已更新部分区域。仅看到进度结束、API 返回空值或出现大面积颜色，都不能确定结果已保存。返回 DRC 空数组表示本次详细检查无报告项；非空时保留原始返回并检查分类、叶项和豁免情况。

何时请用户操作：当前客户端缺少逐区接口、网关无法确认活动板、或 SDK 导出的铜层与客户端显示显著不一致时。优先尝试读回、检查已有作业与区域填充；必要时请用户在铺铜管理器重建或从同一板导出一次诊断包。保存状态有疑问时重开核验。临时填铜处理及提前重建条件遵循[阶段铺铜策略](placement-routing.md#集中布线与阶段铺铜)，不因每次局部写线反复要求用户重铺或导出。

## 从制造文件复核

离线修改源文件前保存并关闭可能覆盖它的客户端文档，或使用经验证的同步方法。只读分析可在客户端开启时进行。写回后重新打开并运行原生检查。

获取独立的、与这版板一致的带网焊盘表，逐项核对器件位姿、焊盘 ID、脚号、网络、所在层和坐标。Gerber ZIP、钻孔和该表必须使用同一原点和方向。脚号可重复（例如连接器的多个屏蔽脚）；给每个物理焊盘一个唯一 ID。预期网络列表取自板端已分配到物理焊盘的网络集合，缺少网名应报错。0 Ω 等器件在装配后建立连接，裸板 CAM 按其两端焊盘网络分别检查。独立列出设计允许相连的 net-tie，当前脚本会将其报告为异网共铜；由设计方按位置核实。

以下为 manifest 的字段示例。真实板必须列全铜层、所有贯通镀孔文件、所有预期网络及所有带网器件焊盘。`layers` 在焊盘条目内表示**明确要求有该焊盘铜的层**，插件孔可按设计列顶底层，不把无焊盘的内层也当作缺铜。圆形 PTH 的层间连接由钻孔文件另行建立。

```json
{
  "bounds_mm": [0, 0, 40, 30],
  "layers": ["top.GTL", "bottom.GBL"],
  "plated_through": ["vias.DRL", "pins.DRL"],
  "nets": ["CLOCK"],
  "pads": [
    {"id": "U1.2", "net": "CLOCK", "xy_mm": [8,10], "layers": ["top.GTL"]},
    {"id": "J1.1", "net": "CLOCK", "xy_mm": [25,10], "layers": ["top.GTL","bottom.GBL"]}
  ]
}
```

使用单独的 Python 环境，安装 numpy、scipy，并提供 pcb-skill 源代码目录。执行前核对 ZIP 中的层和钻孔清单，特别是独立的插件孔、过孔和非金属化孔。通孔表包括全部电气 PTH，排除 NPTH。

```text
python scripts/cam-check.py check.zip manifest.json connectivity.json --pcb-skill PATH_TO_PCB_SKILL --resolution 0.025
python scripts/test-cam.py PATH_TO_PCB_SKILL
```

第二条命令生成临时双层样板，分别检查正常连接、少一个镀孔造成的开路、以及两网意外共铜。Excellon 使用绝对坐标和显式毫米小数；隐含小数格式先由可靠的 CAM 工具转换，再核对钻孔原点与层图叠合。

脚本逐层栅格化实际铜形，标记相接区域，经金属化孔合并各层，再将独立的焊盘网络标签映射到铜。每个预期网应有一个连通体；异网共用的连通体、落不到铜的焊盘均报告。退出码 0 为通过，1 为连通检查失败；解析或输入错误也会非零退出。0.025 mm 是一个验证过的示例分辨率。按最小铜间隙、窄颈及焊盘尺寸选网格，对临界结果用更细网格或矢量 CAM 复核。代码继承上游解析器的格式限制，仅适用于其支持的正铜、圆形贯通镀孔和有铜的焊盘中心采样点；负片、盲埋孔、长槽镀孔、偏置采样点等另选支持这些特性的 CAM。该检查不能发现所有无网孤铜、钻偏或亚像素短路。

## 比较通过后仍要回答的三个问题

1. **回流在何处闭合？** 检查每段信号实际参考层，沿主线和调试支路分别投影至实铜；跨线段合并连续缺口。由信号孔量到同时接入两参考面的地孔。验证新地孔或护线时，排除其自身孤立铜形造成的接地假象，沿实际铜和镀孔确认其并入主地；同时检查孔盘间距、新避空及供电铜颈。记录采样间隔、距离和最差位置。若参考层属于不同电源域，评估合适的跨参考返回结构。中心线覆盖与地孔距离是几何证据，阻抗、抖动和眼图需另行建模或实测。
2. **大电流从哪里进入和返回？** 逐一识别端子、磁珠、分流器电流端、各段铜颈、并联过孔、负载脚、去耦与回流。分开估计铜片直流电阻、焊盘与过孔电阻和瞬态环路电感。没有峰值脉宽、占空比或允许压降时，写明可证实的连通与几何，留下需测的电气条件。
3. **本次试布如何成为正式版？** 先备份正式板；用工程和文档身份锁定写入对象，保持目标文档与板级原理图的关联。保存、重开后核对器件和焊盘映射、几何、网络、规则、实际填充以及副本仍在。最后从正式板获取原生 DRC、Gerber、钻孔、SHA-256；制造说明注明实际叠层、阻抗、开窗、填孔与需板厂确认的公差。


## 工具能力与版本记录

PcbCliTool 0.3.0 / Windows 已在特定六层原生工程上用于读取、项目脚本修改后的读回、重建铺铜、DRC 及诊断 CAM 导出。项目记录的验证日期为 2026-11-21。自定义布线脚本生成候选，CLI 承担其中的读取和验证操作；自带路由能力需按实际命令、输入和结果另行记录。

该版本的一个原生开窗图元在源文件中存在，诊断导出的 GKO 却仅包含外框。复现此类问题时保留最小输入、工具版本与输出，检查预期机械轮廓是否实际进入加工文件。受影响的导出包须修复并复核后才可用于制造。其它图元及版本应独立验证。

后端切换时记录输入哈希、文档身份、命令和成功回执，保持单一写入者，核对解析、规则绑定和导出能力。只在操作需要时切换工具，避免客户端缓存覆盖离线结果。

## 制造交付

准备制造包时，BOM、DNP、贴片面别、坐标、装配图、Gerber、钻孔及叠层/阻抗说明须对应同一修订。按装配厂约定在坐标数据中处理 DNP，并保证装配说明可识别。检查实际铜、阻焊、丝印、铣槽和孔文件，保存文件哈希清单。已有图纸或模型不足以证明安装方向、机械装配或电气能力时，列出需确认的证据和受影响的交付结论。
